## 先に読むもの

1. `CONTENT.md` の「図データ」「解説用の図種」「解説テキスト（学ぶタブ）」の節（データ形式と図の書き方）。それ以外の節は読まなくてよい。
2. 書き方の見本：`data/text/t01-kiso.json` の最初の3節（t01-01〜t01-03）。構成・文体・図の使い方・例題の書き方を揃える。内容は写さない。
3. 章ごとの作業ファイル（`C:\Users\KATSUYA\AppData\Local\Temp\w\`）：
   - `<章id>_syll.txt`：シラバス Ver.9.2 の該当中分類（小項目と用語例が全部載っている）。節はこの小項目（（1）（2）や①②）の単位に対応させ、**用語例に挙がる語は漏らさず本文で説明する**（深さは項目ごとに調整してよい。試験での出題頻度が高い計算・用語・区別は深く、周辺は要点中心）。隣り合う小項目を1節にまとめてよい。
   - `<章id>_q.txt`：既存の問題の要約（id | syllabusRef | tags | 問いの末尾）。各節の `questionTags` は、ここに出てくる tags から該当するものを選ぶ（実在する tag だけ。該当が無ければ省略）。既存問題の数値・事例・文言を本文の例題にそのまま使わない（別の数値・事例にする）。
   - `<章id>_g.txt`：用語集の用語。本文中の用語集にある語は自動でタップ可能になるので、用語集と同じ表記で書く。

## 内容の方針

- すべてオリジナルの文章・図・例題・数値にする。IPAの過去問、市販テキスト、Wikipedia 等の文章や図を写さない。
- 各節の構成の目安：要点（`points`、2〜4個）→ 概念の説明（`p`）→ 図・表 → 手順（`steps`）→ 具体例（`example`、答えは途中式つき）→ 取り違えやすい点（`note` の `kind: "pitfall"`）／コツ（`tip`）。節ごとに全部は不要。
- **分量**：1章で、初学者が20〜30分で読める量を目安に、本文（text・items・answer の合計）で 9,000〜14,000 字、節は 10〜16 個。シラバスが広い章（セキュリティ、システム開発技術、企業と法務、経営戦略など）は 18,000 字程度まで、節は 20 個程度まで広げてよい。1節 600〜1,200 字。
- **図**：章全体で 8 個以上（内容が図に向かない章でも、表・流れ図・階層図・並びの図などを工夫して使う）。種類は `layers／flow／venn／bar／seq／tree／state／arrow／gantt／network／er／logic` から内容に合うものを選ぶ。図のラベルは短く。
- 数式・上付き下付きは `^{}` `_{}` 記法。HTML は使わない。
- 試験で問われる角度（計算問題の解き方、用語の区別、似た用語の取り違え）を意識し、「なぜそうなるか」を一文添える。文体は「だ・である」調で章内を統一。親しみやすく、でも正確に。
- 法令・規格・制度に触れる節は、**正確な名称と、2026年10月時点で現行の内容**で書く。確信が持てない数値・条文・年は書かず、報告で挙げる。必要なら Web で一次情報（所管官庁、e-Gov、規格団体）を確認してよい。
- 2027年度の新試験制度の内容は扱わない（Ver.9.2 基準）。シラバスの誤記と思われる箇所は、正しい表記で書いて報告する。

## データ形式

CONTENT.md のとおり。`schemaVersion: 1`、章 `id` は `tNN`、節 `id` は `tNN-01`〜、`subject: "A"`、`field` と `category` は指示された値、`title` は「第N章 ○○」、`summary` は2〜3文。節の `title` は「N.M ○○」の形。各節の `verification` は `{ "status": "unverified", "methods": [], "verifiedAt": null }`。block の type は `h／p／list／steps／figure／table／code／note／example` のみ。

## 検算

計算を含む例題・数値は node のスクリプトで実際に計算して確かめる（一時ファイルは `C:\Users\KATSUYA\AppData\Local\Temp\w\` に、名前の先頭を `<章id>agent_` にして置く）。暗算だけで書かない。コードを含む場合は、擬似言語の書き方（CONTENT.md の「擬似言語コード」）に従い、トレースを実際に追う。
