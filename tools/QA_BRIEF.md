## 検査の観点

1. 事実関係の誤り（定義・公式・数値・用語の取り違え・規格や法令の名称と内容）。
2. 例題（`example`）の答えと途中式。計算・シミュレーションは node スクリプトで実際に検算する（一時ファイルは `C:\Users\KATSUYA\AppData\Local\Temp\w\` に、名前の先頭を `<章id>qa_` にして置く）。暗算だけで済ませない。擬似言語やコードがあれば、実際にトレースする。
3. 図データ（`figure`）が本文・数値と一致しているか。
4. 紛らわしい／誤解を招く表現、試験で問われる点の抜けや誤った強調。
5. 他の資料（IPA過去問・市販書・Wikipedia）の文章を写したと思われる箇所。
6. 作成者が「不確か」と報告した点、法令・規格・制度・年・数値は、一次情報（所管官庁、e-Gov、規格団体、IPA）を Web で確認する。確認できなかったものは、確認できなかったと明記する。
7. 日本語として不自然な箇所、同じ章内での用語の揺れ（minor でよい）。

## 出力

`C:\Users\KATSUYA\AppData\Local\Temp\w\<章id>qa_findings.json` に JSON 配列で書く。要素：
`{ "section": "t03-04", "blockIndex": 数またはnull, "severity": "blocker|major|minor", "issue": "何が間違いか", "evidence": "根拠（検算結果・出典URLなど）", "fix": "修正案（置き換え後の具体的な文言）" }`
blocker＝事実が誤り、major＝誤解を招く／答えが不正確／試験で重要な点の欠落、minor＝表現の改善。問題が無ければ空配列。
`fix` は、該当ブロックの該当箇所を機械的に置き換えられるよう、**元の文言（`from`）と置き換え後の文言（`to`）**が分かる書き方にする（`"fix": "『元の文言』→『新しい文言』"`）。
