# 解説テキストの「要約（digest）」を書くための指示（作成エージェント向け）

基本情報技術者試験アプリの「学ぶ」タブでは、節ごとに「要約／詳細」を切り替えられる。要約表示の上部に出す、**書き下ろしのまとめ（`digest`）**を、既存の章に書き足す。リポジトリ：`C:\Users\KATSUYA\projects\fe-manabi`。

## 形式

各節（`sections[]`）に `digest` を足す。
```
"digest": {
  "text": "2〜4文（200〜400字）のまとめ",
  "keys": ["押さえる用語・公式・数値・区別", "…（3〜6個）"]
}
```
`CONTENT.md` の「解説テキスト」の節も参照。既存のブロック・points・verification などは変更しない。

## 書き方の方針

- 目的：**その節の本文を読まなくても、試験で必要な骨子が分かり、直前に見直せる**こと。要点（points）の言い換えではなく、points では足りない「何が何だか」「なぜそうなるか」「どう使い分けるか」を補う。
- `text`：節の主題を、定義→仕組み（理由）→試験での使われ方の順に、流れのある文章で。箇条書きにしない。2〜4文、200〜400字。「だ・である」調。
- `keys`：試験に出る形で覚えるべきものを3〜6個。用語の定義（一言で）、公式（`^{}` `_{}` 記法）、代表的な数値、紛らわしい用語の区別（A は〜、B は〜）、手順の要点。各項目は1行（50字程度まで）で、それだけで意味が通ること。
- **本文にない事実・数値を足さない**。本文の内容と食い違わない。計算式・数値・用語は本文と一致させる（`example` の答えと食い違わない）。迷ったら本文のとおりに書く。
- 公式・割合・比率は、**分子・分母や片側／両側などの条件を明記**し、単独で読んでも誤解されないようにする（例：適合率の分子は「該当と判定して実際に該当だった数」。「正しく判定した数」だけでは正解率と混同する）。例題の数値を keys に入れる場合は、条件（何の数値か）も添える。
- keys は1項目が約50字以内。長くなる式は法則名を添えて短くする。「具体的でない文」（〜がある、〜を使う）は避け、何が何なのかを書く。
- 用語集の用語は、用語集と同じ表記で書く（自動でタップできるようになる）。
- 本文・points の文をそのまま写さない（言い換え・再構成する）。
- HTML は使わない。

## 手順

1. 対象の章の JSON（`data/text/<file>.json`）を読む。
2. 各節の `digest` を、node のスクリプトファイル（`C:\Users\KATSUYA\AppData\Local\Temp\w\` に `<章id>digest_` の接頭辞で置く）で書き足す。日本語を含む書き換えに Python のヒアドキュメントは使わない。書き戻しは `JSON.stringify(j, null, 2) + '\n'`。
3. 検査（`<file>` と `<章id>` は指示された値）。OK になるまで直す：
```
node -e "import('./tools/validate-core.js').then(m=>{const j=JSON.parse(require('fs').readFileSync('data/text/<file>.json','utf8'));const e=m.checkText(j,'<章id>');console.log(e.length?e:'OK')})"
```

## 報告

5行以内：節数、digest の平均字数、本文と食い違いそうで判断に迷った箇所（あれば）。
